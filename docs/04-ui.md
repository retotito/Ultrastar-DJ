# 04 — UI: windows, MVVM, design tokens, controls

## Windows

| Window | Class | Notes |
|---|---|---|
| DJ | `DjWindow` | Main window; closing it closes the beamers and exits the app |
| Beamer 1 / 2 | `BeamerWindow` | Created by `DisplayService.Open(displayId)`: a normal 960×540 window on the DJ window's screen (beamer 2 cascaded); the DJ drags it to the projector. Fullscreen via the Displays panel, double-click or `F` — on whatever screen it is on; `Esc` only leaves fullscreen; pointer hides after 2 s in fullscreen; never has focus-stealing dialogs |

Both are plain Avalonia `Window`s in the same process. Beamers are **pure views**: their `BeamerViewModel`
subscribes to `PlaybackService` state and `GameSession` messages and holds only view state (countdown value,
score animation).

Beamers are **not owned** by the DJ window: an owned window always stays in front of its owner (macOS and Windows), so
the DJ window could never come back to the front on a shared screen. `DisplayService` closes them on the DJ window's
`Closing` instead. There is no screen picker: choosing a monitor in code behaves differently per OS, dragging a window
does not. Closing one beamer (title bar or panel) leaves the other open and raises `OpenStateChanged` for the panel.

│ display│        │ status · song · badges          │   │ │ list          │  │

Sidebar buttons open **popover panels** (not modal dialogs): Song Sources, Audio Input (players/mics),
Audio Output, Displays, Settings. Audio Input/Output/Displays are disabled while a song is active.
One popover at a time, in a shared frame (`DjWindow`): header with icon, title and ✕ (from
`DjWindowViewModel.PanelTitle/PanelGlyph`), scrolling body below. Panel views therefore have no title of their own;
their actions sit in a right-aligned row at the top of the body. Another sidebar button switches; the same button,
the ✕, or a press anywhere outside the popover and the sidebar buttons closes it (the press still reaches its target).
Drop-downs and menus opened from a panel count as inside (checked via the logical tree — their lists are drawn outside
the panel's visual tree). The Game Player card (`NowPlaying*` in code) is not a popover —
it stays open until its own close button — but shares its look: one `Border.popover, Border.card.floating` style
(no shadow spread: Avalonia draws spread shadows with square corners) and the same header (icon, title, ✕, divider;
the header is also its drag handle). Nothing between the window's Canvas and the card may clip (`ClipToBounds`), or the
shadow is cut to a square.

Interaction states: `BrushStateHover` (on-surface 10%), `BrushStatePressed`, `BrushStateSelected`,
`BrushStateSelectedHover` — Fluent's list highlight on the OS accent colour (light 0.4/0.6/0.7, dark 0.6/0.8/0.9).
Used by library and list rows, queue rows (loaded song = selected), sidebar navigation and all `Button.sidebar` icon
buttons (active = selected), toggle buttons (checked = selected) and an active tonal button (mic Test).

Pictures per song (`Core.Songs.SongPicture`, tested): **picture** = cover → YouTube thumbnail (only when YouTube is
the video source; cached by `ThumbnailService`) → background; **backdrop** = background → cover. `PlaybackService`
loads both once per game song (after the media, so a slow thumbnail never delays loading); the preview player loads
its own picture the same way.

What fills the beamer background and the Game Player box is one rule, `Core.Playback.StageView` (tested), over the
six media cases:

| State | Beamer | Game Player box |
|---|---|---|
| Loaded (home) | start view | picture |
| Get ready | picture, blurred | picture |
| Countdown | picture, dimmed | picture |
| Playing / paused | video (cases 2, 3, 4, 6; picture under it until the first frame) or backdrop, dimmed (cases 1, 5) | same |
| Score | picture, blurred | picture |

Both boxes have the same height (`PlayerPictureHeight`). `VideoSurface` is transparent until its first frame and
clears when its `FrameBus` gets a new song.

Disabled state: every disabled control is dimmed to `OpacityDisabled` (0.4, also used for unavailable library rows)
with the normal arrow cursor (global style in `Controls.axaml`). `ToolTip.ShowOnDisabled` is on for all windows, so a
disabled control's tooltip says why it is disabled.

Tooltips: Settings → "Show tooltips" (on by default) sets the app resource `ShowTooltips`; the global `Window` style
binds the inherited `ToolTip.ServiceEnabled` to it, so one switch covers every tooltip in every window.

Cursors: pointing hand on everything clickable (global style in `Controls.axaml`); draggable areas use
`GrabCursors.Grab` (macOS open hand = `StandardCursorType.DragMove`) and `GrabCursors.Grabbing` while dragging (a fist
drawn in code — Avalonia has no closed-hand cursor; `SizeAll` is a crosshair on macOS).

Context menus, `MenuFlyout`s and ComboBox drop-downs use the same shadow (`ShadowOverlay` token). They open in their
own popup windows that end at their content, so `Controls.axaml` gives them a transparent `ShadowRoom` margin and
offsets the popup by the same amount to keep the menu where the theme puts it.

## MVVM rules

- `CommunityToolkit.Mvvm`: `ObservableObject`, `[ObservableProperty]`, `[RelayCommand]`, `WeakReferenceMessenger`.
- ViewModels contain **no** Avalonia types (no `Brush`, `Bitmap`, `Window`). Views bind to primitive/record
  state; converters or custom controls turn it into visuals.
- Services (`PlaybackService`, `DisplayService`, `MediaChannel`s, `PlayersService`, …) are injected into
  ViewModels via constructor. Views are located by convention (`FooView` ↔ `FooViewModel`) using a small
  `ViewLocator`.
- Cross-VM communication goes through the messenger with **record** messages defined in `App/Messages/`.
  Do not let ViewModels reference each other.
- Anything that updates ≥ 20 Hz (levels, positions, ticks) bypasses `INotifyPropertyChanged` and drives a
  custom control directly (`InvalidateVisual`) — property-change storms are the #1 Avalonia perf mistake.
- Dialogs/popovers open via a `IDialogService`, never `new Window().Show()` inside a ViewModel.

Rules (identical in spirit to the prototype):
- **Never** hardcode colours, sizes or font sizes in a view. Always `{DynamicResource ColorX}` / `{StaticResource SpaceN}`.
- New token → add to `Tokens.axaml` (and the light variant). Never define ad-hoc resources inside a view.
- Base theme: Avalonia **Fluent** with our colour resources overriding the palette. Component styles live in
  `Styles/Controls/*.axaml` (buttons, text fields, sliders, cards) — one file per control family.
- Icons: **Material Symbols** as a font (`Assets/Fonts/MaterialSymbolsOutlined.ttf`) via an `Icon` control
  taking the glyph name (`<c:Icon Name="mic_external_on"/>`). Same names as the prototype.

## Beamer view states

`BeamerView` switches on `PlaybackState`:

| State | Content |
|---|---|
| Idle | logo / "Ultrastar DJ" |
| Preview | background (cover blurred), title, artist, assigned player badges |
| Countdown | background + big 3 / 2 / 1 |
| Playing / Paused | `VideoSurface` (or image) + `GameOverlayControl` (lanes, lyrics, progress) + "PAUSED" overlay |
| Score | all players, animated scores, winner highlight; stars in the winner's colour once counted |

Beamer reports `BeamerReady` once its `VideoSurface` is subscribed and the first layout pass is done, and
`CountdownDone` when its own 3-2-1 finishes.

## UI inspector (Debug builds)

Avalonia's Developer Tools are paid (Plus plan), so `App/Diagnostics/UiInspector.cs` covers the basics, compiled
only in Debug. In any window:

- **F12** toggles inspection of that window: the control under the mouse is outlined (margin dashed) and a separate,
  always-on-top **UI Inspector** window shows it — type, `#Name`, `.classes`, active pseudo-classes (`:pointerover`…),
  the `.axaml` file it is written in (or the control whose template it belongs to), DataContext type,
  size/position/margin/padding/alignment, visible/enabled/opacity, text, font, colours, corners, and the full path.
- **Alt/Option+click** pins a control (orange outline) so the mouse can travel to the inspector window; the click does
  not reach the app. The next Alt+click anywhere, or the inspector's **Unpin** button, releases it and hovering
  follows the mouse again.
- **Copy** puts the details on the clipboard; **Dump tree** or **Shift+F12** writes the window's visual tree to
  `logs/visual-tree-<Window>-<time>.txt`, the inspected control marked `◀ INSPECTED` — hand that file to an agent
  instead of describing the UI. Closing the inspector window turns inspection off everywhere.

Not covered: popups (ComboBox drop-downs, flyouts) are separate top levels; no live property editing.

## Errors and notifications

All user-facing messages go through `NotificationService`; no red inline error texts in views.

| Level | When | API | Looks like |
|---|---|---|---|
| Toast | Something happened, no decision needed (guest request, mic plugged, offline / back online, USDB down) | `Info` / `Success` / `Warn` | Top-right card, icon + title + detail, ✕; 5 s (warnings 8 s) |
| Error dialog | An action the DJ started failed (load/preview a song, playback stopped, folder scan, songbook start) | `ShowError(title, reasons, details)` | Centred; one plain sentence per reason; "Show details" reveals the raw cause |
| Bug dialog | Unexpected exception | `ShowBug(ex, context)` — called by the global handlers in `App` | "Something went wrong", Copy details (stack trace), Open log folder; the app keeps running |

Dialogs queue (OK shows the next); the same bug is not queued twice. Media failures are translated by
`Media.PlaybackError.Explain` (yt-dlp's error line → "age-restricted", "no longer available", "no connection", …);
`MpvPlayer` passes yt-dlp's message instead of mpv's "unrecognized file format". Panel status lines stay only for
hints about the panel itself ("Stop the mic test before refreshing"). Debug builds: Shift+F8 shows test toasts,
Shift+F9 raises a test exception.

Connectivity: `ConnectivityService` probes `youtube.com/generate_204` at start, on OS network changes and every 15 s
("network up" is not enough). Offline → warning toast, USDB songs greyed out; back online → success toast, USDB
un-greyed or logged in again. A USDB toast appears only when the internet works but USDB does not.

## Things agents get wrong in Avalonia (read this)

- `x:Class` must match the code-behind class exactly (case-sensitive).
- Use `DynamicResource` for colours that change with theme; `StaticResource` for spacing/fonts.
- `Dispatcher.UIThread.Post` (not `Invoke`) from background threads; never block the UI thread waiting for mpv/PortAudio.
- `WriteableBitmap.Lock()` must be paired with dispose; copy the frame **inside** the lock and invalidate after.
- Avalonia `ListBox` virtualization requires a fixed-height item template and `VirtualizingStackPanel`.
- No WPF-only APIs (`Freezable`, `VisualBrush` tricks, `RenderTargetBitmap.Render` semantics differ). If an
  API is not in the Avalonia docs, it does not exist.
- Multi-window: each `Window` needs its own `DataContext`; do not share a ViewModel instance between beamers.
